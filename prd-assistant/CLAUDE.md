# Food Lab PRD Assistant

기획자/디자이너를 위한 PRD 작성 도우미

---

## 소개

**Food Lab PRD Assistant**는 기획자와 디자이너가 Claude Code Desktop 앱에서 바로 사용할 수 있는 PRD 작성 도구입니다.

- **코드 작성 불필요**: 기술적 지식 없이 문서 작성에만 집중할 수 있습니다
- **Notion + Figma 연동**: 업무 도구와 직접 연결되어 자동으로 문서를 읽고 쓸 수 있습니다
- **User Story 자동 분해**: 큰 기능을 작은 단위로 나누고 실행 가능한 형태로 만들어줍니다
- **디자인 Draft 생성**: Figma에 바로 디자인 초안을 생성할 수 있습니다

## 행동 규칙

- 요구사항이 모호하면 반드시 **먼저 질문**하고 진행한다
- 되돌리기 어려운 작업 전에는 항상 **확인을 요청**한다
- 가정을 세울 경우 **명시적으로 밝히고 동의**를 구한다
- 문서 작성 전에 **어떤 내용을 어떻게 작성할지 계획을 먼저 보여주고** 승인을 받는다
- **실수 발생 시**: 근본 원인을 분석하고 재발 방지 방법을 함께 논의한다
- **[절대 규칙] 작업 착수 전 Skill 매핑 확인 필수**: 사용자 요청을 받으면, 작업 **전에** 반드시 아래 "사용 가능한 스킬" 테이블을 확인하여 매칭되는 skill이 있는지 점검한다. 매칭되는 skill이 있으면 **반드시 해당 skill을 통해 작업**한다.

### 혼란 관리 프로토콜 (Confusion Management)

작업 도중 불확실한 점이 발생하면, 추측으로 진행하지 않고 아래 형식으로 구조화하여 사용자에게 제시한다:

```
CONFUSION:
{무엇이 불확실한가}

Options:
A) {선택지 1} — {장단점}
B) {선택지 2} — {장단점}
C) 사용자에게 질문 — {이유}

→ 어떤 접근을 선호하시나요?
```

**적용 시점**:

- 요구사항이 2가지 이상으로 해석될 수 있을 때
- 여러 선택지가 있을 때
- UX 동작에 대한 명시적 지시가 없을 때

**[절대 금지]** 혼란 상태에서 가장 그럴듯한 옵션을 골라 설명 없이 진행하는 것. "그럴듯하다"는 판단 근거가 아니다.

### 가정 표면화 프로토콜 (Assumptions Surfacing)

문서 작성, 설계, 분석 시 세운 가정은 반드시 명시적으로 나열하고 사용자 확인을 받는다:

```
ASSUMPTIONS:
1. {가정 1}
2. {가정 2}
3. {가정 3}
→ 틀린 것이 있으면 지금 교정해주세요. 이대로 진행합니다.
```

**적용 시점**: 계획 수립, 기능 범위 결정, 데이터 구조 해석, UX 동작 추론, 외부 서비스 동작 가정

**[절대 금지]** 가정을 세운 채 밝히지 않고 진행하는 것. 밝히지 않은 가정은 나중에 "왜 이렇게 했어?"라는 질문을 유발한다.

### UX 명확화 게이트 (UX Clarification Gate)

UI/UX 동작을 기획할 때, 아래 항목 중 하나라도 명시적 지시가 없으면 **추측하지 않고 반드시 질문**한다:

| 카테고리      | 질문 대상 예시                          |
| ------------- | --------------------------------------- |
| **로딩 상태** | 스켈레톤 vs 스피너 vs 없음              |
| **에러 표시** | 토스트 vs 인라인 vs 모달 vs 에러 페이지 |
| **빈 상태**   | 안내 메시지 vs 일러스트 vs CTA 버튼     |
| **상태 전환** | 애니메이션 유무, 방향, 속도             |
| **반응형**    | 데스크톱 전용 vs 반응형 breakpoint      |
| **접근성**    | aria-label 필요 여부, 키보드 탐색       |
| **확인/취소** | 모달 확인 vs 즉시 실행 vs Undo 패턴     |

**[절대 금지]** "일반적으로 이렇게 하니까", "보통은 이렇게" 같은 이유로 UX 동작을 임의 결정. Figma에 명시되어 있으면 Figma를 따르고, 없으면 사용자에게 질문한다.

### 기능 완전성 체크리스트 (Feature Completeness Checklist)

기능을 기획할 때, 구현 전에 아래 항목을 반드시 점검한다:

- [ ] **빈 상태**: 데이터가 0건일 때 어떻게 보여줄지
- [ ] **경계값**: 0건, 1건, 최대값(페이지당 표시 한계 등) 처리
- [ ] **에러 상황**: 네트워크 실패, 타임아웃, 권한 오류 시 사용자에게 보이는 화면
- [ ] **동시 수정**: 여러 사용자가 동시에 수정할 때 어떻게 처리할지
- [ ] **되돌리기**: 사용자가 실수를 바로잡을 수 있는 방법

누락 항목이 있으면 "처리 안 함"이 아니라 "어떻게 처리할지 사용자에게 질문"한다. 의도적 미처리는 문서에 이유를 남긴다.

## MCP 서버 설정

이 패키지는 **Notion**과 **Figma**와 연동하기 위해 MCP(Model Context Protocol) 서버를 사용합니다.
Node.js 설치 없이, Claude Code Desktop 채팅창에서 아래 명령어를 실행하면 자동으로 연결됩니다.

### Notion MCP 연결 (원격 HTTP 방식)

Claude Code Desktop 채팅창에서 아래 명령어를 입력합니다:

```
claude mcp add --transport http notion https://mcp.notion.com/mcp
```

### Figma MCP 연결 (공식 플러그인 방식)

Claude Code Desktop 채팅창에서 아래 명령어를 입력합니다:

```
claude plugin install figma@claude-plugins-official
```

### 연결 확인

MCP 서버가 정상 연결되었는지 확인하려면 채팅창에서 아래와 같이 입력합니다:

```
/mcp
```

Notion과 Figma가 목록에 표시되면 정상입니다.

## 사용 예시

### 1. PRD 작성

```
/prd https://notion.so/your-page-id
```

Notion 페이지의 기획 내용을 분석하여 PRD를 작성하고, User Story를 자동으로 분해합니다.

### 2. 디자인 Draft 생성

```
/figma-make-design "사용자 프로필 수정 화면"
```

설명을 기반으로 Figma에 디자인 초안을 자동 생성합니다.

### 3. 기획 검증

```
/grill-me
```

작성한 기획서나 PRD에 대해 체계적인 질문을 통해 빠뜨린 부분이 없는지 검증합니다.

## 주의사항

- **API 토큰은 외부에 공유하지 마세요**: 토큰이 노출되면 다른 사람이 여러분의 Notion/Figma에 접근할 수 있습니다
- **작업 전에 항상 계획을 확인하세요**: Claude Code가 제시한 계획을 검토하고 승인한 후 진행합니다
- **큰 기능은 작은 단위로 나누세요**: `/incremental-impl` skill을 활용하여 실행 가능한 크기로 분해합니다
- **Figma 링크는 정확히 복사하세요**: URL이 정확해야 디자인을 읽고 쓸 수 있습니다
