# Grill-Me — 설계 검증 Skill

기획/설계 결정에 대해 체계적으로 질문하여 견고함을 검증한다. 비즈니스 판단이 필요한 미결 사항을 구조화된 질문으로 정리하여 사용자에게 제시한다.

---

## 트리거 키워드

"설계 검증", "grill me", "그릴 미", "질문 공세", "스트레스 테스트", "design review", "기획 리뷰"

## 워크플로우

### 1단계: 입력 수집

사용자에게 검증할 대상을 요청한다:

- PRD 문서 또는 기획서
- 설계 결정 문서
- 구현 계획 설명
- Notion 페이지 URL
- 자유 형식 설명

### 2단계: 문서 분석

입력된 문서를 분석하여 질문할 영역을 식별한다:

- **범위 분석**: 기능의 포함/제외 경계가 명확한지
- **사용자 플로우 분석**: 사용자 시나리오에 빠진 경로가 없는지
- **비즈니스 규칙 분석**: 규칙의 예외 상황이 처리되었는지
- **UX 분석**: UI/UX 동작이 명확하게 정의되었는지
- **의존성 분석**: 외부 시스템, 다른 기능과의 의존관계가 명확한지
- **에지 케이스 분석**: 경계값, 빈 상태, 에러 상황이 고려되었는지

### 3단계: 구조화된 질문

분석 결과에서 **불확실하거나 누락된 사항**을 질문한다.

**질문 규칙:**

- **한 번에 3~5개 질문**을 그룹으로 제시 (10개를 한꺼번에 던지지 않는다)
- 각 질문에 **추천 답변(recommended answer)**을 반드시 함께 제시
- 추천 답변은 문서 분석 결과에 기반한 근거 포함
- 사용자가 추천 답변에 동의하면 "ㅇㅇ" 또는 "추천대로"만으로 빠르게 진행 가능

**질문 카테고리:**

| 카테고리        | 설명                                                        | 예시                                        |
| --------------- | ----------------------------------------------------------- | ------------------------------------------- |
| **[범위]**      | 기능의 포함/제외 경계                                       | "이 기능에 권한 관리도 포함하나요?"         |
| **[우선순위]**  | 구현 순서, MVP vs 후순위                                    | "에러 핸들링은 1차에 포함? 2차?"            |
| **[기술 제약]** | 기술적 제약 사항                                            | "기존 시스템과 호환성 문제는 없나요?"       |
| **[UX]**        | 사용자 경험, 인터랙션 방식                                  | "로딩 상태는 스켈레톤? 스피너?"             |
| **[UX 명확화]** | Figma/명세에 없는 UI 동작 (로딩, 에러, 빈 상태, 애니메이션) | "데이터가 0건일 때 화면은 어떻게 보이나요?" |
| **[데이터]**    | 데이터 구조, 입출력 형식                                    | "새 필드의 데이터 타입과 제약조건은?"       |
| **[비자동화]**  | 수동 작업 필요 항목                                         | "이 설정은 누가 수동으로 수행하나요?"       |
| **[비즈니스]**  | 비즈니스 규칙, 정책                                         | "동일 사용자가 중복 요청하면 어떻게 처리?"  |

### 4단계: 라운드 반복

- 사용자 답변을 받으면 후속 질문이 필요한지 판단
- 새로운 미결 사항이 발견되면 추가 라운드 진행
- 각 라운드의 Q&A를 기록

### 5단계: 최종 판정

모든 미결 사항이 해결되면 최종 판정을 내린다:

```
## 설계 검증 완료

**판정**: 설계가 견고합니다.

### 확인된 결정사항
- {확정된 결정 1}
- {확정된 결정 2}
- {확정된 결정 3}

### 주의사항
- {구현 시 주의할 점}

### 후속 검토 권장 사항 (있으면)
- {추가로 검토가 필요한 영역}
```

미결 사항이 남아있으면:

```
## 설계 검증 미완료

**판정**: 미결 사항이 있습니다.

### 미결 사항
- {해결되지 않은 질문/결정}
```

## PRD Skill과의 연동

PRD skill의 3단계(Clarification Interview)에서 이 패턴을 내부적으로 사용한다.
독립 실행도 가능하고, PRD 워크플로우 내에서도 호출된다.

---

## 자기합리화 방지 (Anti-Rationalization)

| 자기합리화                | 현실                                                                |
| ------------------------- | ------------------------------------------------------------------- |
| "충분히 물어봤다"         | 3~5개 미만의 질문으로는 설계 검증이 불가능하다. 최소 1라운드는 필수 |
| "추천 답변이 맞을 것이다" | 추천은 제안이지 사실이 아니다. 사용자 확인 없이 확정하지 않는다     |
| "문서를 다 분석했다"      | 모든 섹션을 점검했는지 다시 확인하라                                |

---

## 위험 신호 (Red Flags)

이 스킬 실행 중 아래 신호가 보이면 즉시 멈추고 재검토한다:

- 1라운드만에 "설계가 견고합니다" 판정
- UX 동작에 대한 가정을 질문 없이 확정
- 추천 답변 없이 열린 질문만 제시
- 에지 케이스(빈 상태, 에러 상황)를 한 번도 질문하지 않음

---

## 완료 증거 (Verification)

아래 항목이 모두 충족되어야 완료:

- [ ] 최소 1라운드의 Q&A 완료
- [ ] 모든 질문에 추천 답변 포함
- [ ] 문서 분석 수행 (범위, UX, 비즈니스 규칙, 에지 케이스 등)
- [ ] 최종 판정(견고/미완료) 선언

"괜찮아 보인다"는 증거가 아니다.

---

## 핵심 규칙

1. **문서 분석 먼저, 질문 나중**: 문서에서 파악할 수 있는 것은 직접 분석한다
2. **추천 답변 필수**: 모든 질문에 근거 기반 추천을 함께 제시
3. **3~5개 그룹핑**: 질문 과부하를 방지하여 사용자의 의사결정 품질을 높인다
4. **카테고리 태깅**: 질문의 성격을 명확히 하여 사용자가 맥락을 빠르게 파악
5. **최종 판정 필수**: 미결 사항이 없을 때 "설계가 견고합니다"로 명확히 종결
