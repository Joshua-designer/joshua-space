# Incremental Implementation — 점진적 분해 Skill

큰 기능을 thin vertical slice로 분해하고, 각 slice를 micro-task 단위로 만들어 실행 가능한 크기로 관리한다.

---

## 트리거 키워드

"점진적 구현", "vertical slice", "micro task", "incremental", "단계별", "작은 단위", "thin slice", "잘게 쪼개"

---

## 워크플로우

### 1단계: Vertical Slice 분해

전체 기능을 **사용자 시나리오를 완전히 관통하는** vertical slice로 분해한다.

```
기능: "원료 검색 필터 추가"
├─ Slice 1 (Tracer Bullet): 단일 필터(이름) — 전체 사용자 플로우 관통
├─ Slice 2: 카테고리 필터 추가
├─ Slice 3: 복합 필터 (이름 + 카테고리)
└─ Slice 4: 필터 초기화
```

**Tracer Bullet 선정 기준**: 전체 사용자 플로우를 관통하는 가장 핵심적인 1개 slice

### 2단계: Micro-task 분해

각 slice를 아래 기준으로 micro-task로 분해한다:

| 기준            | 규칙                                |
| --------------- | ----------------------------------- |
| **독립성**      | 각 task가 독립적으로 완료 가능      |
| **검증 가능성** | 각 task에 구체적 Done Criteria 포함 |
| **크기**        | 1개 task가 명확히 정의된 작은 단위  |
| **순서**        | 단순 → 복잡 순서로 정렬             |

```
Slice 1의 Micro-tasks:
├─ Task 1-1: 검색 기능 요구사항 정의 + AC 작성
├─ Task 1-2: 검색 UI 디자인 가이드라인 작성
├─ Task 1-3: 디자인 DRAFT 생성 + 리뷰
└─ Task 1-4: 개발팀 전달용 명세서 정리
```

### 3단계: 순차 실행

1. **Tracer Bullet slice 먼저 완료** → 사용자에게 전체 방향 확인
2. 나머지 slice 순차 진행
3. 각 task 완료 시 진행 상황 기록
4. 문제 발생 시 즉시 사용자에게 보고

### 4단계: 전체 검토

- 모든 slice 완료 후 전체 기능의 완전성 확인
- 누락된 시나리오나 에지 케이스가 없는지 점검
- 의존성 그래프 최종 확인

---

## Micro-task 분해 예시

| 좋은 예                               | 나쁜 예                                  |
| ------------------------------------- | ---------------------------------------- |
| "검색 기능 요구사항 정의"             | "검색 기능 전체 기획"                    |
| "단일 필터 UI 디자인 가이드라인 작성" | "전체 UI 한 번에 디자인"                 |
| "카테고리 필터 AC 작성하여 동작 확인" | "나중에 한꺼번에 검증"                   |
| "이전 task와 독립적으로 완료 가능"    | "3개 task가 동시에 완성되어야 의미 있음" |

---

## 자기합리화 방지 (Anti-Rationalization)

| 자기합리화                      | 현실                                                            |
| ------------------------------- | --------------------------------------------------------------- |
| "한 번에 기획하는 게 더 빠르다" | Big Bang 기획은 리뷰 시간이 작성 시간보다 길다                  |
| "이건 분해할 수 없다"           | 분해할 수 없다면 이해가 부족한 것이다. 먼저 더 분석하라         |
| "micro-task가 너무 사소하다"    | 사소한 task는 확실히 완료된다. 큰 task는 "거의 완료"에서 멈춘다 |
| "검증은 마지막에 한꺼번에"      | 마지막에 문제가 발견되면 어디가 원인인지 알 수 없다             |

---

## 위험 신호 (Red Flags)

이 스킬 실행 중 아래 신호가 보이면 즉시 멈추고 재검토한다:

- 1개 task의 범위가 지나치게 넓다
- task 간 의존성이 과도하게 복잡하다
- 3개 이상의 task가 동시에 완성되어야 동작한다
- Tracer Bullet 없이 여러 slice를 동시에 진행하려 한다

---

## 완료 증거 (Verification)

아래 항목이 모두 충족되어야 완료:

- [ ] 모든 slice가 사용자 시나리오를 완전히 관통
- [ ] 각 micro-task에 Done Criteria 포함
- [ ] Tracer Bullet slice가 최우선으로 배치
- [ ] 의존성 그래프가 명확
      "기획을 다 작성했다"는 증거가 아니다. 실행 가능한 단위로 분해되어야 증거다.

---

## 핵심 규칙

1. **Vertical Slice**: 각 slice가 사용자 시나리오를 완전히 관통하도록 분해
2. **Tracer Bullet 우선**: 전체 방향 검증이 끝나야 나머지 slice를 시작
3. **각 task에 Done Criteria**: "무엇이 되면 완료인가"를 task 정의 시 명시
4. **점진적 복잡도**: 단순 → 복잡 순서로 정렬하여 리스크를 조기에 발견
5. **독립성**: 각 task가 독립적으로 완료 가능해야 한다
